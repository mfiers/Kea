Kea turns a data analysis into a website of linked claims and evidence that readers comment on, and that an AI agent revises in review cycles, release by release.

What it does

Typed pagesQuestions, premises, hypotheses (stated before or after the results), steps, results, conclusions, caveats, figures, data files, glossary terms and references, each on its own page and linked by typed relations: supports, opposes, tests, limits.
Evidence attachedEvery number points to the file it comes from. Code pages have line anchors. Data files have checksums and downloads. Every figure has a full caption and links to its table and script.
Review cyclesReaders select text and comment, or suggest an edit. A PI presses Harvest and the agent folds the comments into a plan; then Implement. The agent makes the changes and releases a new semantic version.
What changed, and how settledA change log per agent run. A history of every review cycle. Each page shows when it last changed and whether its claim changed, so settled parts stand out from parts in flux.

How to use it: through an AI agent

Kea is meant to be run by an AI coding agent: Claude Code, or another agent harness that can read a skill file and run shell commands. The agent installs the tool, sets up the pages, runs the analysis through them, serves the site, watches for comments and runs the review cycles. You talk to the agent and read and comment on the site. Installing and running Kea by hand is possible but is not the intended way to use it: keeping the pages, hypotheses, change logs and review cycles consistent is the work the agent does.

Installing the tool yourself

The agent normally does this, but to have the kea command on a machine (for example a hub host), install a tagged version with uv. Kea is not on PyPI.

uv tool install git+https://github.com/mfiers/Kea.git@v1.19.0     # the kea command, for any project
uv add "kea @ git+https://github.com/mfiers/Kea.git@v1.19.0"       # or: a dependency of a Python/uv project
uvx --from git+https://github.com/mfiers/Kea.git@v1.19.0 kea --help  # or: run once without installing

Upgrade by running the same command with the new tag (uv tool install --force …@vX.Y.Z); uv tool upgrade kea does not move a pinned tag. Needs git; the PDF needs Typst.

mkdir -p ~/.claude/skills/kea

Other agents: put skill/SKILL.md wherever your agent reads its instructions, for example in the project's agent instructions file.

2. Say "use Kea"

In your project, tell the agent "use Kea". It asks for a short outline of the project and its first experiment, unless that is already clear. It then installs a tagged version of Kea, writes the first pages, builds the site, agrees with you on where to host it (on your own machine unless you need more), gives you the link and starts watching for comments. From then on, ask it to work on a question: it reads what the site already holds for that question before it starts (kea context).

Reading a Kea site

A Kea site documents one analysis as small pages, one idea per page, linked by typed relations (supports, opposes, answers, tests, limits). The project's home page has its summary; each experiment's page has its own summary and every question with its answer in short; a question page leads with its conclusions and results; the details sit one click further down.

Goalthe experiment's home page: its summary and every question with its answer in short
Premisewhat the analysis takes as given
Questionwhat is asked; leads with its answer in short, its conclusions and results
Hypothesiswhat was expected, and whether it was written before its test
Stepwhat was done (methods)
Decisiona choice made along the way, why, and the alternatives
Resultwhat a file shows; every number comes from a named file
Conclusionwhat the results mean, with the evidence for and against
Figurea figure with its full caption
Artefacta data file, with checksum and download
Caveatwhat limits a result or a conclusion
Terma glossary entry; words with a dotted underline link to it
Referencea paper, with its abstract and why it is cited
  • Tags are links. Every page has a coloured tag with its type's icon and a number (Q1, R2, C3). The tag is always the link to that page, and hovering it shows the page's one-line summary. In a list of pages the whole line is the link; in running text only the tag is.
  • Status. The pill next to a tag is the page's status: green settled or supported, amber exploratory or open, red rejected. Hypotheses say whether they were written before their test or after the results.
  • The menu bar shows where you are: Kea (home) / project / experiment / page. When space is short, the menu folds first and the page title stays longest. The kea logo opens the site's help page.
  • Comments and edits. Select text and press Comment. The Edit button in the menu bar opens the page's Markdown; the pencil beside a section heading edits only that section. Edits are saved as suggestions and folded into the next review cycle.
  • Versions. The project's version belongs to its set of pages. The site and the PDF are two views of the same version; the PDF carries it on its title page.

Analysis runs that build on what is known

Before the agent works on a question, kea context <question> prints the part of the knowledge tree it has to take into account: the answer so far, earlier results and hypotheses, the premises, the decisions in force, every caveat on those pages and on the method, open comments, and what is still missing. The skill makes this the first step of every run. The agent then fixes and commits its hypotheses before the test, runs the analysis from scripts, writes results with their source files, checks the caveats again, and updates the answer and the summaries.

Saying use Kea to the agent starts it in order. It asks for an outline of the project and the first experiment, sets up the pages and builds the site. It then agrees on hosting (localhost unless you need more), sends you the link and starts watching for comments.

The review cycle

  1. Comment. Readers select text and comment, or suggest an edit, for as long as the round takes. The agent's watcher waits without spending tokens; comments alone do not wake it.
  2. Harvest. A PI presses Harvest. The agent folds every comment into one plan, which then stands until the next harvest. The plan page counts the comments made since.
  3. Implement. A reader presses Implement. The agent makes the changes and records them in a change log. It answers every comment with the commit that dealt with it.
  4. Release. The agent tags a semantic version: major when a conclusion changes direction, minor for new results, patch for wording. Open pages reload, and comments reopen. Comments that were not in the plan stay for the next cycle.

Small enough to change while you use it

Kea is about 4,000 lines of Python and 700 lines of its own JavaScript and CSS, with nine Python dependencies. It has no database: pages are Markdown in git, and comments are an append-only log. The site is static HTML, rebuilt in seconds. So the agent running your review cycle can also change the tool during the session when you ask: a new page type, a different menu, a public build. Most of Kea's features were added that way, at a reader's request.

Builds

kea build builds the review site with comments. kea build --mode local builds a static copy without comments, with links into the project's data, to read from disk. kea build --mode public --out DIR builds a copy for any web host. It contains no comments, no data files and no previews of controlled tables, and it lists what it left out.

kea pdf puts every page into one PDF, typeset with Typst and ordered for a reader on paper. Each experiment opens with its conclusions; the methods follow, then each question with its hypotheses, results and figures, then the caveats. An appendix gives overview tables of every page, numbered references in journal style and what changed in each version. Cross-references carry page numbers, and a closing chapter explains how to read it. The title page carries the project's summary, its version, the author and the repository; with more than one experiment the next page summarises each. kea build adds it to the site, linked from the home page, and recompiles it only when the pages change. Typst is optional; without it Kea writes the source file and says how to install it.
