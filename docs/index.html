Kea turns a data analysis into a website of linked claims and evidence that readers comment on, and that an AI agent revises in review cycles, release by release.

What it does

Typed pagesQuestions, premises, hypotheses (stated before or after the results), steps, results, conclusions, caveats, figures, data files, glossary terms and references, each on its own page and linked by typed relations: supports, opposes, tests, limits.
Evidence attachedEvery number points to the file it comes from. Code pages have line anchors. Data files have checksums and downloads. Every figure has a full caption and links to its table and script.
Review cyclesReaders select text and comment, or suggest an edit. The agent folds the comments into a plan. Readers freeze the site and press Implement. The agent makes the changes and releases a new semantic version.
What changed, and how settledA change log per agent run. A history of every review cycle. Each page shows when it last changed and whether its claim changed, so settled parts stand out from parts in flux.

Install the skill (Claude Code)

The skill tells Claude how to set up Kea in a project and how to run the review cycle. Install it once, and it is available in every project:

mkdir -p ~/.claude/skills/kea
curl -fsSL https://raw.githubusercontent.com/mfiers/Kea/v1.2.0/skill/SKILL.md \
     -o ~/.claude/skills/kea/SKILL.md

Then, in any project, ask Claude something like "set up a kea site for this analysis". Claude installs the tool, runs kea init, writes the first pages and starts the comment server and the watcher.

Install the tool

A Python project (uv)

uv add "kea @ git+https://github.com/mfiers/Kea.git@v1.2.0"

Any other project (R, a plain folder)

uv tool install git+https://github.com/mfiers/Kea.git@v1.2.0

Start

kea init --title "My analysis" --experiment first-experiment --question "What do we ask?"
make site       # build the site from doc/
make serve      # serve it with comments; the password is in .env

Install a tagged version, so a project does not change when Kea does. The newest tags are on the tags page.

The review cycle

  1. Comment. Readers select text and comment, or suggest an edit. The agent's watcher picks the comments up and folds them into one plan. It is token-free while waiting.
  2. Freeze. A reader freezes the site. Comments are then possible only on the plan, which shows whether every comment is in it.
  3. Implement. A reader presses Implement. The agent makes the changes and records them in a change log. It answers every comment with the commit that dealt with it.
  4. Release. The agent tags a semantic version: major when a conclusion changes direction, minor for new results, patch for wording. Open pages reload, and comments reopen.

Small enough to change while you use it

Kea is about 4,000 lines of Python and 700 lines of its own JavaScript and CSS, with nine Python dependencies. It has no database: pages are Markdown in git, and comments are an append-only log. The site is static HTML, rebuilt in seconds. So the agent running your review cycle can also change the tool during the session when you ask: a new page type, a different menu, a public build. Most of Kea's features were added that way, at a reader's request.

Builds

kea build builds the review site with comments. kea build --mode local builds a static copy without comments, with links into the project's data, to read from disk. kea build --mode public --out DIR builds a copy for any web host. It contains no comments, no data files and no previews of controlled tables, and it lists what it left out.

kea pdf puts every page into one PDF, typeset with Typst: a chapter per experiment, figures with their full captions, a glossary and a reference list, and every cross-reference as a link. kea build adds it to the site, linked from the home page, and recompiles it only when the pages change. Typst is optional; without it Kea writes the source file and says how to install it.
