## Asked

Mark Fiers, 12 November 2026: the hub should give an elegant message for a project that has been added (`kea hub add`) but has not published yet. 13 November 2026: reassess the site on a phone: colours in the menu's dropdown are off (dark on black, hard to see) and scrolling is awkward. Then: the menu bar is always dark, so keep it light text on a dark background everywhere; mark states with different tints, nothing else.

## Changed

- Hub: before a project's first `kea publish`, its address (`<name>.<domain>` or `/p/<name>/`) shows a page saying the site is not published yet, with links to the hub's projects and help and a short note for the owner (`remote:` in kea.yaml, `KEA_REMOTE_KEY` in .env, `kea build`, `kea publish`). Before, a public project answered with a server error and a private one with its login, then the same error. No sign-in is asked; a private project shows only its name, not its title; the answer is a 404 and not cached. The agent API, sign-in and the comment API (`/api/…`) keep their own access rules.
- Phone: the menu bar stays at the top while scrolling; the folded menu scrolls inside itself when taller than the screen and closes on a tap outside it; the user menu scrolls the same way. The page's own text has less indent and tighter lines (14 px, line height 1.58). The tabs under the separator use short labels (About, Answers) and stay on one row; if the screen is narrower still, the row of tabs scrolls, not the page.
- Menu bar: light text on dark in every state. Fold-outs sit in a slightly lighter navy strip (was a light strip with dark text); the current item is a lighter tint and semibold, an open group's name white (was amber); the folded menu's sub-items are light (were dark on navy); the experiment chip's hover, the ☰ button while open (was the browser's blue) and a differing version line in the user menu use tints too.
- README: one line on the hub's page for projects not published yet.

## Checked

`pytest` (117 tests; new: `test_unpublished_project_says_so_instead_of_failing`: the page on the project's subdomain and on `/p/<name>/`, no private title, the comment API still answers 401, the agent API works, and the site replaces the page after the first publish). Kea's own site built and looked at in headless Chrome: the menu folded and open at 390 px, the tabs at 390 px, the desktop Map fold-out; no page of eight checked scrolls sideways at 390 px. The hub page at desktop and phone width. Not tried on a real phone; the comment panel together with the sticky bar on a phone not checked.
