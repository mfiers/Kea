## Asked

Mark Fiers, 13 November 2026: critically reassess the new Progress view; maybe it should get a top-level menu entry; it is unclear how "Waiting for a sign-off" differs from "Ready for the next step": separate them more, or merge. Then: relabel the Approve & go button on signed-off pages too, release, and tell the sessions.

## Found

Both lists had the same columns and the same "Approve & …" button, and both waited for a reader's click; "Ready for the next step" read as if the agent was already at it. On the S100 site "Ready" offered "draw conclusions" on R13 and R14 while the route table showed Q7's conclusions as closed: `go_action` did not skip answered or dropped questions, and under `pace: free` offered it on every result instead of the newest. Long titles pushed the button column off-screen; "Kind" repeated the badge and "Request" was an empty heading. Progress hid under Plan (the comment cycle). On a page signed off already the button still said "Approve & run the step" and added another signature.

## Changed

- Progress is a top-level menu entry (between Map and Plan) with a count badge in the menu bar's tints; the breadcrumb is Start › Progress; Plan keeps Current comments.
- One table, "Waiting for you · N": page, where it stands (● needs your sign-off; ✓ signed off by … · not started; no sign-off needed · not started) and the button on the page, with a short legend and the live state per row.
- The route table hides the Approved column under `pace: free`; every remaining stage of a closed question reads closed.
- `graph.go_action`: no step on a result of an answered or dropped question; "draw conclusions" only on the newest live result.
- The button on a page that is signed off already (or needs no sign-off) reads "▶ Run the step" (Write the plan, …): the thread text is "Go: …" and adds no signature; a second reader signs with Approve. The tag instruction, `kea watch` and the skill say so; the banner reads "Run the step: …".
- Help (Reviewing) and README describe the new layout.
