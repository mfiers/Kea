## Asked

Mark Fiers, 25 November 2026, after looking at the graph on trajectories.keahub.eu: the graph looks nice. Make it the site's landing page, keep s as "down" on the graph (W A S D complete), merge the graph-view branch and release it.

## Found

The front page was index.html, which the hub and `kea publish` require to exist and which holds comment threads under the key `index.html`. Moving the front page without keeping that key would have orphaned those comments.

## Changed

- index.html now sends readers to the graph (explore.html, with the #page they asked for); it is no page of its own and carries no comments.
- The project's front page (summary, experiments, latest run) is start.html, under its old thread key `index.html`, so earlier comments and its Edit button stay on it. With one experiment the start page is still that experiment's page.
- The kea head in the menu bar opens the graph; the project name, Start in the crumbs and g s open the start page. The graph's fallback links (no JavaScript, no _graph.json) point at the start page.
- Help (Reading) says where the site opens and how to reach the start page.
- Merges the graph view (2026-11-24-a) into main.

Hub: upgrade not needed (static pages and page scripts; index.html still exists; no endpoint, status field or publish format changed).

## Checked

`pytest` (148 passed; a new test builds a two-experiment site: index.html redirects to the graph, start.html is the front page with thread key index.html, the kea head and the project name link the graph and the start page). Headless Chromium against `kea serve` on that site: / and index.html#first:home land on the graph at that page, g s opens start.html with the comment layer, the kea head returns to the graph, Start in the crumbs opens start.html; no script errors.
