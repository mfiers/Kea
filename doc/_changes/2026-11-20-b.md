## Asked

Mark Fiers, 20 November 2026: "Can you critically ensure the agent adheres as much as possible to the most minimal possible graph layout. E.g. anything that can be a node should be a node. Text in a node should be as concise as possible. Larger questions are better split up. Caveats should be that. A single node should be easy to grasp. Never be too wordy. Use precise language."

## Changed

- Skill: a new section "A minimal graph": anything that can be a page is a page (limits as caveats, assumptions as premises, choices as decisions, words as terms, data and tools as resources, follow-ups as questions); one idea per page, a question asks one thing; titles of one line (at most ~16 words), summary lines of one sentence, texts within a ceiling per type (question, hypothesis, premise, caveat, term 90 words of prose; decision, conclusion 130; result 200; step, experiment 250); precise, never wordy. Restructuring a signed page goes through the plan.
- The project CLAUDE.md block (`kea init`) and Kea's own CLAUDE.md carry the rule in one line.
- `kea build` / `kea check` notes: a title over 16 words; a question that asks more than one thing (two question marks, or "…, and how/what/whether …" in the title); text over the type's ceiling (prose only: no tables, code, headings, figures; a link counts as its label); a limit named in the text ("limitation", "caveat", "cannot be ruled out", "confounded by" …) on a page no caveat limits. Notes, not problems: `make site` still passes.

Hub: upgrade not needed (build and agent instructions only).
