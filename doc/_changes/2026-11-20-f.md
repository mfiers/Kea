## Asked

Mark Fiers, 20 November 2026: extend the g menu a little and add page actions behind a (edit title t, edit summary s, edit page p, approve a, take back d, approve & next); n/p for next and previous in an order that is always the same, N/P for the pages that need attention; logical keys for Change, More, Propose and Manuscript, following the logic of the menus.

## Changed

- **a** opens "This page …", grouped as the page's buttons are. Sign-off: a approve this page only, n approve and open the next page that needs attention, d take back your approve before the Harvest. Change: t edit the title in place, s edit the summary in place, p edit the whole page, r revise, x drop. More: c comment, + propose a next step, w work for the next run, m manuscript. Each key does exactly what its button does (feedback.js `keaPageActions`); entries that do not apply are greyed out. A key signs at most the page you are on, and like a click nothing starts: the sign-off waits for the Harvest.
- **n / p** go to the next and previous page in the reading order: every page, top down through each experiment (the order the sign-offs already followed). `kea build` writes it to `_order.json`. **N / P** walk only the pages that need attention, in the same order, wrapping around; from a page outside that list they go to the nearest one after or before it. N used to mean "previous".
- **g** gains: a (the first page that needs attention), l Relations, t Terms, b References, w what changed per session, f the PDF; the menu follows the menu bar's order.
- `signing.sign_order` is now `reading_order` filtered to the pages that wait, so both keys and "Approve & next" walk one order.
- Help (Reading a page) lists the keys.

Hub: upgrade not needed (page scripts and a static `_order.json`, published with the site and served like the other site files).
