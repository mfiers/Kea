## Asked

Mark Fiers, 9 November 2026, about the s100 site: questions, conclusions and hypotheses render well, but terms, resources and references are muddled and embedded inconsistently. Agreed: author–year inside the pill for references, no number.

## Changed

- References get a pill like every other page, holding the author and year ("Akiyama et al. 1994", from the start of the title or from `citation:`), in the text, the menu bar, the page header, the tables and the Objects list. `[[ref-x|Lloyd 2024, p.7]]` puts the given text in the pill. Next to the pill the title drops the author and year it repeats. Terms and references have their own colours.
- Terms are linked at their first use in each section (a `##` heading starts a new one), and now also in table cells (not headers). Resources with `aliases:` (dataset ids such as G23/MIC) are linked the same way, with the resource's title and summary on hover.
- Term and resource pages list "Used on these pages": every page whose text uses the term or alias.
- The summary box is left out when the page text opens with the same sentence (a term's definition).
- The resource fact table has the same look as tables in the text.
- Tables of pages leave out the Status column when no row has a status (references, terms).

## Help for newcomers

- README.md rewritten for a first-time reader (a biologist): why Kea exists, why one claim per page, how a project progresses and is validated (route, hypotheses fixed before the test, one step at a time with verdicts, build checks, rechecks, versions), then reading a site, the review cycle, using it through an agent, and the reference material. Text drafted by a Claude Fable session after reading the whole project, checked against the code.
- The web page (docs/index.html, mfiers.github.io/Kea) is now generated from README.md (`make web`, src/build_web.py), so GitHub and the web page say the same thing; the page-type table takes Kea's own tags and colours.
- The site's help page opens with why small pages, then where to start and how the analysis progresses; status colours corrected (dark red is not supported, deprecated or dropped); the link to Kea's own page points at its reading section.
- Corrected claims: Kea is about 11,500 lines of Python and 1,900 of its own JavaScript and CSS, not 4,000 and 700; the kea head goes home (Help is on the right); Edit is among the page buttons, not in the menu bar; only a PI presses Implement.
