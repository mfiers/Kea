## Asked

Mark Fiers, 18 November 2026: there is no option to create a new experiment on the project page; then: release, and tell the trajectories session.

## Found

On a project with two or more experiments the front page (index.html) is not a typed page: the dock showed only Comment (and Edit with doc/_summary.md), and "Propose ▸ an experiment" was offered only on an experiment's own page. On a project with one experiment the front page is that experiment's page, where the option was already there.
- Reported by the blood2brain session after the upgrade to 1.29.0: `kea context <experiment>` named only the question-level steps under "Next step on the route"; premises, decisions and the experiment, which wait for a sign-off since 1.29.0, were not named, so an agent following it would not ask the owner.

## Changed

- The front page marks itself as the project page; the dock shows "Propose ▸" there with "an experiment" (the propose-experiment tag now applies to experiment and project pages). The agent writes the experiment in the next run, as with every proposal.
- Under the experiments table a line says how to add one.
- `kea context` (next steps on the route) first names the experiment, premises and decisions that wait for a sign-off.

## Checked

`pytest` (128 passed; new: the context names a waiting premise); `node --check` on feedback.js; a scratch project with two experiments builds with the marker, the hint and the feedback script on index.html.
