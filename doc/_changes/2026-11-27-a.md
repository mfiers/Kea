## Asked

Mark Fiers, 27 November 2026, after trajectories was emptied for a clean slate: the project is empty and it is not clear how to start on the website (Propose ▸ …); make that more prominent, certainly on an empty experiment.

## Found

On an experiment without questions nothing said what to do. The way in was Propose ▸ an experiment, two clicks deep under More ▸ in the page buttons, and on an existing experiment it proposes a new experiment, not the brief for this one. The graph, where the site opens, showed the empty experiment as "No pages yet", and Space on that row did nothing.

## Changed

- An experiment without questions opens with a box "Start here: write the brief", above its text: what to write (in plain words what the experiment should find out, which questions it asks, the data if known), the route it starts (under `pace: design`: brief, design, sign, execute, review; under `guided` and `free` their own steps) and a button "Write the brief" that opens a text field in the box. Send saves a comment tagged `brief`; the box then shows the brief, who sent it and when, and what comes next (Harvest, then Implement). Once the brief is on the page and still no question exists, the box says the design comes next and offers "Add to the brief". The box goes when the first question exists. Without the comment layer it says to tell Claude in chat.
- New proposal tag `brief` (experiment pages, whole page only, text required): Claude copies the text word for word under `## Brief` on this experiment page and, under `pace: design`, writes the whole design in the same plan item, then stops for the sign-off. It also appears under More ▸ Propose on experiment pages.
- On the graph the empty experiment's row reads "Start here: write the brief", in the colour of proposals, and Space or a click opens the experiment page.
- `kea context`, the skill and Help (How a project progresses) name the box as a place the brief comes from.
- After sending a proposal the message says what was saved (a brief, a proposal, a revision); before, a brief would have read "the revision is asked".

Hub: upgrade not needed (page text, page scripts and a tag that ships in the site's own `_feedback/tags.json`, which the hub checks comment tags against; no endpoint, status field, event or publish format changed).
