## Asked

Mark Fiers, 9 November 2026, after 1.19.0: the permanent identifiers on the line of "About this page", left, small and grey, copied on a click; a pencil on the page kind ("Question Q1") that opens the whole-page editor; in the name menu, the hub's front page and the reader's other projects.

## Changed

- The identifiers (`kea:…` and `@…`) sit on the separator line, left; a click copies the link (Ctrl/Cmd-click still opens it) and says "copied".
- Hovering the page kind shows a pencil (only for readers who may edit); it opens the whole-page editor, the same as Edit in the page menu.
- The question's "Answer so far" lost its explanatory note; under the answer, "From" links the conclusions and results it rests on.
- A regression test: comments readers made on the hub survive every later publish and any seed (the hub's log is the authority; a seed only fills an empty log). wiskelab had found the kea project's hub logs empty after a publish on 8 November; the code never truncates them, so they were most likely empty before.
- One experiment: the site starts at its page (`index.html` redirects; no experiment level in the menu bar and breadcrumbs; the project title stays). The experiment page gets what the project page had: the help line, the project summary when it differs, the latest run and the site's own pages. `kea new experiment <name> --title` adds one; from two experiments on, the project page is the start again and `kea check` requires `doc/_summary.md` (front matter now optional). Readers can Propose ▸ an experiment; under pace: guided an experiment waits for approval before questions go under it.
- Phone cards: the status pills flow at the end of the title line; no column of their own, no indent.
- On a hub, `/api/status` carries the hub's front page and the reader's other projects (with an ORCID account: those with a role, with the role; with a project password: the public ones); the name menu lists them under "Kea hub" and "Other projects".

## Checked

`pytest` (104 tests; new: the hub links in the status, hub logs never shrink). Identifier copy and the kind pencil in a headless Firefox (the click copies and does not navigate; the pencil opens the editor).

## Not done
