## Asked

Mark Fiers, 27 November 2026: an MCP connection to check pages, find how they connect and sign them, for Claude's voice mode, with a custom URL that circumvents the current authentication.

## Changed

- The hub answers MCP (streamable HTTP, stateless, JSON) at `<hub>/mcp/<token>`, a personal capability link: `kea hub mcp add --orcid … | --name … --projects …  [--sign] [--label …] [--days 90]`, `kea hub mcp list`, `kea hub mcp revoke <id>`. The hub keeps only a hash; the link is never written to the hub's log.
- Tools: list_projects, overview (questions, pages waiting for a sign-off, held pages, the cycle), get_page (state, version, text, what it builds on and what builds on it), connections (up or down, several links deep), path_between, search; with a signing link also sign_page and comment.
- sign_page signs one page, exactly like Approve on the site: an approve thread bound to the version read, marked "by voice"; it needs the PI or director role, the current version, and a second call with confirmed=true after the person says yes. It becomes a signature at the harvest and can be withdrawn on the site until then. No batch signing over MCP.

Hub: upgrade needed (new route /mcp/ and the `kea hub mcp` command). Sites need no rebuild (the link reads `_graph.json`, `_ids.json` and the sources already published).
