## Asked

Mark Fiers, 20 November 2026, on nbraak-pseudotime q-pit-cohorts: under "Builds on these questions and decisions" Q1 still said "waiting for approval" although he had just approved it; can this update faster, or is it built statically?

## Found

It was built statically: the pill comes from the last `kea build`, and an approve on the site waits for the Harvest before Claude writes it onto the page and rebuilds. Only the approved page's own button knew of it.

## Changed

- Every "waiting for approval" pill carries its page's key; when the comment server's status lists the page as approved on the site (`status.signing`), kea.js turns it into "signed · waits for Harvest" (green, dashed) at once, and back if the approve is taken back. This covers every list that shows the pill: a page's relation tables, Progress, the objects tables.
- The question strip's tags get the same mark (dashed green).
- Help (Reviewing) updated.

Hub: upgrade not needed (page scripts and a data attribute; status.signing exists since 1.31).

## Checked

`pytest` (142 passed). Headless Chromium on a scratch guided project with the comment server: S1's page listed H1 as "waiting for approval"; after approving H1 on its own page, S1's page showed "signed · waits for Harvest" for H1 in both tables and H1's tag in the strip dashed green. No script errors.
