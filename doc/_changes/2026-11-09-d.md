## Asked

- Mark Fiers, 9 November 2026: show clearly which version is running, for the site and for the hub.
- Mark Fiers via joost-s100-be, 9 November 2026: `kea publish` sends the whole site as one upload with a 30 s timeout, so the 11 MB s100 site fails at about 280 kB/s ("The write operation timed out"). Send only what changed, in chunks that can resume, with a timeout per chunk.

## Changed

- `kea publish` is incremental. The hub keeps every file of a project once, by sha256 (`projects/<name>/blobs/`). The client sends the list of files with their checksums, the hub answers which it lacks (and how much of a broken upload it already holds), and only those go up, in 4 MB chunks, each with its own timeout and up to four tries. The release is then made from the stored files (hard links, no copies). Unchanged files, such as the PDF and figures, are sent once. Blobs no kept release uses are removed after a day.
- Against a hub before 1.21 the client falls back to the single upload, with a timeout that grows with the upload size (at least 60 s, assuming 50 kB/s).
- Hub API: `POST blobs/missing`, `POST blobs/<sha256>?offset=&total=`, `POST release`. `POST publish` stays for older clients. Release paths must lie under site/, doc/ or files/; a file whose checksum does not match is discarded.
- A small grey pill in the menu bar: the Kea version that built the site (hover: also the site's own version). With a comment server or hub it adds that server's Kea version when it differs ("Kea 1.21.0 · hub 1.20.0", in amber), and says so in the hover either way. Hidden on phones.
- The hub's own pages (landing, your projects) show the hub's Kea version next to its domain. `/api/status` reports `server_version` and whether it is a hub. `/healthz` stays plain "ok" (uptime monitors may match it exactly).
