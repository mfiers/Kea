## Asked

Mark Fiers, 18 November 2026: for people allowed to, a Harvest/Implement button in the top menu bar (a variant on the play button).

## Found

Harvest and Implement were only on the plan page. Harvest and Implement (also on the plan page) failed with an alert "set your name first" for a reader who had not commented yet.

## Changed

- One button in the menu bar for readers who may steer (a PI or director account on a hub, the iteration password, or a site without one); others see nothing. It follows the cycle: "⇣ Harvest · N" when N comments wait outside the plan; "▶ Implement" (green tint, with the same confirmation as the plan page) once the plan stands and has items; "⟳ Harvesting", "▶ Implement asked" and "⟳ Implementing" while Claude works (these open the plan page). The plan page keeps Harvest again and Cancel.
- `_build.json` records the number of items per cycle plan, so the button knows whether there is anything to implement.
- Harvest, Implement and Cancel ask a reader without a name for it first (as a comment does) instead of failing.
- Help (reviewing).

## Checked

`pytest` (129 passed). In headless Chromium on `kea serve` with a scratch project: with one comment the bar shows "⇣ Harvest · 1"; the click asks the name and the request is recorded (state harvest-requested, by the name given), the button turns into "⟳ Harvesting"; after a plan with one item and `kea cycle plan-updated`, "▶ Implement", the confirmation, then "▶ Implement asked"; with `can_steer` false in the status the bar has no button.
