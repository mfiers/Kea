## Asked

Mark Fiers, 19 November 2026: the overall diff on a commit page is too much and can get large; drop it and leave the diffs to the individual pages. And: when deciding which files go up to the hub, anything under 10 kB can go without a doubt.

## Changed

- A commit page keeps its message, the comments it answered and its files. Each file shows added / changed / removed, its size of change ("+12 −3 lines") and "what changed →", which opens that page's Changes tab with the word diff for that page alone. The whole-commit diff is gone; it ran to 500 lines per commit.
- A run page lists its pages added, changed and removed the same way: "what changed →" replaces the raw diff under "show the change".
- `kea publish`: `upload_max_kb` defaults to 10, so data files up to 10 kB go up without asking. Files that may hold identifiers (donor, subject, sample … columns) or that Kea cannot inspect (h5ad, parquet …) still stay home unless named in `upload_include`. `upload_max_kb: 0` sends none. The skill, the project template for CLAUDE.md and the README say the same: ask the owner only about larger files.

Hub: no upgrade needed.

## Checked

`pytest` (131 passed; the test of the old diff renderer removed; the upload test now checks the 10 kB default, the identifier flag at that size, and `upload_max_kb: 0`). Kea's own site: 0 problems; the largest commit page is 70 kB.
