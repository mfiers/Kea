## Asked

A long series of site changes asked by Mark Fiers on 8 November 2026: one-click tags and page verdicts, an editor with a text and a raw mode, in-place edits of title and summary, a clear split between a page's content and what Kea knows about it, tables instead of cards, a colour review, a simpler menu, an Objects page for thousands of pages, the experiment's home page as its own type, a round logo, and the same upgrades in the PDF. Also: answer the hub's question about per-project subdomains, and record the design on [[roadmap:s-stable-ids]].

## Changed

- Selection popup: Comment, Edit (the paragraphs that hold the selection), one-click tags for the next run and for the manuscript, with Undo.
- Page buttons in a column at the bottom right, folded by the kea badge: Comment, Edit, Confirm, Reject, Next run, Manuscript. Confirm and Reject are definitive requests for the next plan; a confirmation ends up as `confirmed:` in the page's front matter and shows as a pill.
- Editor: Text mode (title, summary, body; type and relations not editable) and Raw Markdown mode, both with highlighting; title and summary also edited in place (pencil in the margin).
- Page layout: the page's own content in a serif font; below a rule in the type's colour, "About this page" with one table per kind of link, worded with the type ("Tested by this step"); status pills on the line of the kind label; a type bar with icon along the left edge.
- Tables: full width, page / in short / status, a 4 px status bar on each row; the front page and the Objects page use them too.
- Colours: white text now passes 4.5:1 on every type colour; rejected status darker than the conclusion red; filled buttons slate instead of a blue close to question blue (independent review, 8 November).
- Menu: Map (Relations, Objects › Data, Code), History (Review cycles, Plan, Comments), PDF; the logo opens Help. Objects: search, filters by type and status, sorting, 50 rows a page (tested with 3,000 pages).
- The experiment's home page is type `experiment` (was `goal`; old projects still load, with a note).
- Logo: the kea icon is kept; a round badge made from it is the menu-bar logo, page button and favicon.
- PDF: new colours, status bars on table rows, an "About this page" block after each section with the site's wording, confirmations in the header.
- The "new version" notice now appears only when the content changed (the build id is a content fingerprint).

`pytest` (71 tests), `kea check`, `kea build --strict`, the PDF built with Typst, and every change looked at in a browser (headless Firefox screenshots).

## Later in the run: permanent page ids, step 1

Every page has a `uid:` (`kea check --fix` mints them; `kea check` reports malformed and duplicate ones); the build writes `_ids.json`; `/id/<uid>` on the site redirects to the page and `/id/<uid>.json` gives its facts; "About this page" shows `kea:<uid>`. Tested with `tests/test_identity.py` and on the dev server.

## Later in the run: version ids, the hub resolver and subdomains (Kea 1.13.0)

Version ids per page state (shown as `@<version>` beside the permanent id); `/id/<uid>@<version>` shows a stored earlier version on a hub. The hub keeps every published page version, refuses ids that belong to another project, resolves `/id/…` on the apex, and serves each project on `<project>.<project_domain>` when hub.yaml sets `project_domain` (reserved names refused). Coordinated with the infrastructure session (wiskelab): wildcard certificate for `*.keahub.eu` is live.
